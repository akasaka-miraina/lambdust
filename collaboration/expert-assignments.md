## 🔄 協業パターン定義

### パターン1: 設計→実装
**参加者**: 設計者(architect) → 実装者(rust-expert)  
**フロー**: 
1. 設計者がアルゴリズム・アーキテクチャ策定
2. 実装者が技術的制約・最適化案提示
3. 協議・調整後、実装者が実装実行
4. 設計者が結果検証・フィードバック

**適用例**: メモリ最適化、SIMD設計、分散アルゴリズム

### パターン2: 共同設計・実装
**参加者**: 複数専門家の同等協業  
**フロー**:
1. 共同で要件分析・設計協議
2. 並行して各担当部分実装
3. 定期的統合・調整会議
4. 共同テスト・検証

**適用例**: 継続システム、JIT統合、複雑マクロシステム

### パターン3: 独立実装→レビュー
**参加者**: 主実装者 + レビュアー  
**フロー**:
1. 主実装者が独立実装
2. 定期的進捗報告
3. 完了後、専門家レビュー
4. フィードバック・改善

**適用例**: 標準ライブラリ、テストスイート、エラー処理

### パターン4: 仕様確認→実装
**参加者**: 仕様専門家(language-processor/r7rs) → 実装者  
**フロー**:
1. 仕様専門家が要件・制約確定
2. 実装者が実装案提示
3. 仕様適合性確認・調整
4. 実装実行・仕様再確認

**適用例**: R7RS準拠機能、言語仕様実装

## 📅 週次協業スケジュール

### 毎週月曜 (週次全体会議)
**参加者**: 全専門家  
**議題**:
- 前週進捗報告・課題共有
- 今週計画・協業ポイント確認
- ブロック要因解決・リソース調整
- リスク管理・スケジュール調整

**時間**: 1時間  
**成果物**: 週次進捗報告・課題管理表更新

### 毎週水曜 (中間チェック)  
**参加者**: 関連専門家  
**形式**: 協業グループ別ミーティング
- グループA: language-processor + rust-expert
- グループB: cs-architect + rust-expert  
- グループC: lambdust-r7rs (進捗報告のみ)

**時間**: 30分/グループ  
**目的**: 協業作業の中間調整・課題解決

### 毎週金曜 (技術レビュー)
**参加者**: 完了作業関連専門家  
**議題**:
- 完了作業のコードレビュー
- 技術的品質確認
- 次週作業への影響分析
- 学習事項・改善提案

**時間**: 45分  
**成果物**: レビュー結果・改善提案書
