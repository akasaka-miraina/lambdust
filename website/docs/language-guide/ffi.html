Foreign Function Interface (FFI)

Lambdust's FFI system enables seamless integration with existing C/C++, Rust, and system libraries while maintaining the language's type safety and purity guarantees. The FFI is designed to be both safe and performant, with zero-cost abstractions for well-typed foreign calls.

extern "C" : (CType → IO CType) — Safe foreign function binding

Basic FFI Declarations

Foreign functions are declared using the extern keyword with explicit type annotations:

C Library Integration

;; Basic C function binding
(extern "C" strlen : (CString → CSize))
(extern "C" malloc : (CSize → IO (Ptr Void)))
(extern "C" free : (Ptr Void → IO Unit))

;; Mathematical functions from libm
(extern "C" sin : (CDouble → CDouble))
(extern "C" cos : (CDouble → CDouble))
(extern "C" sqrt : (CDouble → CDouble))

Type Safety in FFI

Lambdust's type system ensures that foreign function calls are safe:

;; Safe string operations
(define safe-strlen : (String → IO Nat)
  (lambda (str)
    (do-io
      [c-str ← (string→cstring str)]
      [len ← (pure (strlen c-str))]
      [_ ← (free-cstring c-str)]
      (return (csize→nat len)))))

;; Memory management with resource tracking
(define with-malloc : (∀ (α : Type) → CSize → (Ptr Void → IO α) → IO α)
  (lambda (size action)
    (bracket
      (malloc size)           ;; Acquire
      (lambda (ptr) (free ptr))  ;; Release
      action)))               ;; Use

Effect Tracking for Foreign Functions

Foreign functions that perform side effects are properly tracked in the type system:

File I/O with Effect Tracking

;; POSIX file operations
(extern "C" open : (CString → CInt → IO CInt))
(extern "C" read : (CInt → Ptr Void → CSize → IO CSize))
(extern "C" write : (CInt → Ptr Void → CSize → IO CSize))
(extern "C" close : (CInt → IO CInt))

;; High-level file reading with proper effects
(define read-file : (String → IO (Either Error String))
  (lambda (filename)
    (with-handler
      [(SystemError e) → (return (Left e))]
      (do-io
        [c-name ← (string→cstring filename)]
        [fd ← (open c-name O_RDONLY)]
        [content ← (read-all-bytes fd)]
        [_ ← (close fd)]
        [_ ← (free-cstring c-name)]
        (return (Right (bytes→string content)))))))

Rust Interoperability

Lambdust provides special support for Rust libraries through extern "Rust":

;; Rust function bindings with ownership semantics
(extern "Rust" vec_new : (Unit → RustVec α))
(extern "Rust" vec_push : (RustVec α → α → Unit))
(extern "Rust" vec_len : (RustVec α → USize))

;; Safe Rust vector operations
(define rust-vector-demo : (IO Unit)
  (lambda ()
    (do-io
      [vec ← (pure (vec_new))]
      [_ ← (pure (vec_push vec 42))]
      [_ ← (pure (vec_push vec 84))]
      [len ← (pure (vec_len vec))]
      (println (format "Vector length: ~a" len)))))

Zero-Copy String Interop

Efficient string sharing between Lambdust and foreign code:

;; Zero-copy string operations
(extern "C" regex_match : (CString → CString → CBool))

(define match-pattern : (String → String → Bool)
  (lambda (pattern text)
    (with-cstrings ([c-pattern pattern] [c-text text])
      (cbool→bool (regex_match c-pattern c-text)))))

Advanced FFI Features

Callback Functions

Lambdust functions can be passed as callbacks to foreign code:

Event Handling with Callbacks

;; Callback type definitions
(define-foreign-type EventCallback (CInt → CString → IO Unit))

;; Register callback with C library
(extern "C" register_event_handler : (EventCallback → IO Unit))

;; Lambdust callback implementation
(define event-handler : EventCallback
  (lambda (event-type message)
    (do-io
      [msg ← (cstring→string message)]
      (println (format "Event ~a: ~a" event-type msg)))))

;; Register the callback
(register_event_handler event-handler)

Structure Marshaling

Complex data structures can be marshaled between Lambdust and foreign code:

;; C structure definition
(define-foreign-struct Point
  [(x : CDouble)
   (y : CDouble)])

(define-foreign-struct Rectangle  
  [(top-left : Point)
   (width : CDouble)
   (height : CDouble)])

;; Functions operating on foreign structures
(extern "C" calculate_area : (Rectangle → CDouble))

;; Safe structure creation and usage
(define rect-area : (Real × Real × Real × Real → Real)
  (lambda (x y w h)
    (let ([rect (make-Rectangle 
                  (make-Point (real→cdouble x) (real→cdouble y))
                  (real→cdouble w)
                  (real→cdouble h))])
      (cdouble→real (calculate_area rect)))))

Memory Management

Lambdust provides several strategies for safe memory management with foreign code:

RAII-style Resource Management

;; Automatic resource management
(define-resource-type FileHandle
  [acquire: (lambda (filename) (open filename O_RDWR))]
  [release: (lambda (handle) (close handle))])

;; Safe file operations with guaranteed cleanup
(define write-and-sync : (String → String → IO (Either Error Unit))
  (lambda (filename content)
    (with-resource (FileHandle filename) fd
      (do-io
        [bytes-written ← (write fd content)]
        [_ ← (fsync fd)]
        (return (Right unit))))))

Foreign Memory Pools

;; Memory pool for foreign allocations
(define-foreign-pool native-pool
  [allocator: malloc]
  [deallocator: free]
  [alignment: 8])

;; Pool-managed allocations
(define process-large-data : (List Real → IO Real)
  (lambda (data)
    (with-pool native-pool
      (do-io
        [c-array ← (list→carray data)]
        [result ← (native-compute c-array (length data))]
        (return (cdouble→real result))))))

Performance Optimizations

  • Zero-cost foreign calls: Direct function calls with no boxing overhead
  • Compile-time marshaling: Data conversion optimized at compile time
  • Inline foreign code: Small foreign functions can be inlined
  • SIMD integration: Vector operations through foreign SIMD libraries

SIMD Vector Operations

;; AVX2 vector operations
(extern "C" avx2_add_vectors : (Ptr CFloat → Ptr CFloat → Ptr CFloat → CInt → IO Unit))

;; High-level vector addition with SIMD
(define vector-add-simd : (Vector Real → Vector Real → Vector Real)
  (lambda (v1 v2)
    (assert (= (vector-length v1) (vector-length v2)))
    (let ([len (vector-length v1)]
          [result (make-vector len 0.0)])
      (with-carray-views ([a1 v1] [a2 v2] [ar result])
        (avx2_add_vectors a1 a2 ar len))
      result)))

Error Handling

Foreign function errors are integrated into Lambdust's effect system:

;; Foreign error handling
(define-foreign-error LibcError
  [(errno : CInt)
   (message : String)])

;; Safe foreign call with error handling  
(define safe-foreign-call : (String → IO (Either LibcError String))
  (lambda (input)
    (with-handler
      [(ForeignError errno) → 
       (return (Left (LibcError errno (strerror errno))))]
      (do-io
        [result ← (some-foreign-function input)]
        (return (Right result))))))

Platform-Specific FFI

Lambdust supports platform-specific foreign interfaces:

;; Platform-conditional FFI
(cond-expand
  [windows
   (extern "stdcall" GetSystemTime : (Ptr SystemTime → IO Unit))
   (define get-current-time : (IO SystemTime)
     (lambda ()
       (do-io
         [time-ptr ← (malloc (sizeof SystemTime))]
         [_ ← (GetSystemTime time-ptr)]
         [time ← (peek time-ptr)]
         [_ ← (free time-ptr)]
         (return time))))]
  
  [unix
   (extern "C" gettimeofday : (Ptr TimeVal → Ptr Void → IO CInt))
   (define get-current-time : (IO TimeVal)
     (lambda ()
       (with-malloc (sizeof TimeVal) ptr
         (do-io
           [_ ← (gettimeofday ptr null)]
           (peek ptr)))))])

Best Practices

  1. Always specify effects: Mark foreign functions with appropriate effect annotations
  2. Use resource management: Employ RAII patterns for automatic cleanup
  3. Validate foreign data: Check foreign function return values and validate data
  4. Minimize marshaling: Use zero-copy operations when possible
  5. Handle errors properly: Integrate foreign errors into the effect system
  6. Document foreign interfaces: Clearly document foreign function behavior and safety requirements

Safety Considerations

While Lambdust's FFI is designed to be safe, foreign functions can still violate memory safety. Always validate foreign function behavior and use appropriate resource management patterns.
