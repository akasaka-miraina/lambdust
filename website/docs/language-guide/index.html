Lambdust Language Guide

This comprehensive guide covers all aspects of the Lambdust programming language, from basic syntax to advanced features like dependent types and effect systems.

Language Overview

Lambdust is a pure functional programming language that combines the mathematical elegance of languages like Haskell with the practical flexibility of gradual typing. It's designed for both academic research and real-world applications.

Key Characteristics

  • Pure Functional: All functions are pure by default, with effects explicitly tracked
  • Gradual Typing: Start dynamic, add types incrementally
  • Dependent Types: Types can depend on values for precise specifications
  • R7RS Compatible: Full Scheme R7RS compliance with modern extensions
  • Effect System: Monadic programming with algebraic effects
  • Foreign Interface: Safe integration with C/C++, Rust, and system libraries

Core Language Features

Syntax & Semantics

S-expression syntax with modern type annotations and pattern matching.

(define (factorial n)
  (if (<= n 1) 1
      (* n (factorial (- n 1)))))

Monadic Purity

Referential transparency with controlled side effects through monadic composition.

(define read-file : (String → IO String)
  (lambda (filename) ...))

Foreign Function Interface

Safe integration with external libraries while maintaining type safety.

(extern "C" strlen : (CString → CSize))

Performance

JIT compilation, SIMD optimizations, and zero-cost abstractions.

;; Compiled to efficient native code
(define sum-vector : (Vector Real → Real))

Basic Data Types

Primitive Types

;; Numeric types
42                    ; Integer
3.14159              ; Real  
22/7                 ; Rational
2+3i                 ; Complex

;; Text types
"Hello, Lambdust!"   ; String
#\λ                  ; Character

;; Boolean type
#t                   ; True
#f                   ; False

;; Unit type
unit                 ; Single value of unit type

Composite Types

;; Lists (linked lists)
'(1 2 3 4 5)         ; List of integers
'(a b c)             ; List of symbols

;; Vectors (arrays)
#(1 2 3 4 5)         ; Vector of integers

;; Pairs and tuples
(cons 1 2)           ; Pair
'(1 . 2)             ; Pair literal

;; Records
(define-record Point (x y))
(Point 10 20)        ; Record instance

Function Definition and Application

Basic Functions

;; Simple function definition
(define add
  (lambda (x y) (+ x y)))

;; Shorthand syntax
(define (add x y) (+ x y))

;; Function application
(add 3 4)            ; Result: 7

;; Higher-order functions
(define (twice f x) (f (f x)))
(twice (lambda (x) (* x 2)) 5)  ; Result: 20

Functions with Type Annotations

;; Typed function
(define add : (Number → Number → Number)
  (lambda ((x : Number) (y : Number))
    (+ x y)))

;; Polymorphic function
(define identity : (∀ α. α → α)
  (lambda (x) x))

;; Function with effects
(define print-and-return : (∀ α. α → IO α)
  (lambda (x)
    (do-io
      [_ ← (println x)]
      (return x))))

Control Structures

Conditional Expressions

;; If expression
(if (> x 0) "positive" "non-positive")

;; Multi-way conditional
(cond
  [(< x 0) "negative"]
  [(= x 0) "zero"]
  [(> x 0) "positive"]
  [else "impossible"])

;; When and unless
(when (> x 0)
  (println "x is positive"))

(unless (null? lst)
  (process-list lst))

Pattern Matching

;; Basic pattern matching
(match value
  [0 "zero"]
  [1 "one"]
  [n "other number"])

;; List pattern matching
(match lst
  [() "empty list"]
  [(cons x ()) "single element"]
  [(cons x xs) "multiple elements"])

;; Record pattern matching
(match point
  [(Point x y) (+ x y)])

Module System

Module Definition

;; Defining a module
(module math.utils
  (export factorial fibonacci gcd)
  
  (define (factorial n)
    (if (<= n 1) 1
        (* n (factorial (- n 1)))))
  
  (define (fibonacci n)
    (if (< n 2) n
        (+ (fibonacci (- n 1))
           (fibonacci (- n 2)))))
  
  (define (gcd a b)
    (if (= b 0) a
        (gcd b (remainder a b)))))

Module Import

;; Import with prefix
(import (prefix math. "math/utils"))
(math.factorial 5)

;; Import specific bindings
(import (only "math/utils" factorial gcd))
(factorial 5)

;; Import all bindings
(import "math/utils")
(factorial 5)

Effect System

Lambdust tracks side effects in the type system using monads and algebraic effects:

;; Define effects
(define-effect IO)
(define-effect State)
(define-effect Error)

;; Pure computation
(define pure-computation : (Integer → Integer)
  (lambda (n) (* n n)))

;; Computation with I/O
(define io-computation : (String → IO String)
  (lambda (filename)
    (do-io
      [content ← (read-file filename)]
      [_ ← (println "File read successfully")]
      (return content))))

;; Computation with multiple effects
(define stateful-io : (Integer → IO State Integer)
  (lambda (n)
    (do-monad
      [current ← (get-state)]
      [_ ← (put-state (+ current n))]
      [_ ← (println "State updated")]
      (return current))))

Error Handling

;; Using Maybe for optional values
(define safe-divide : (Number → Number → Maybe Number)
  (lambda (x y)
    (if (= y 0) (None)
        (Some (/ x y)))))

;; Using Either for error handling
(define parse-integer : (String → Either String Integer)
  (lambda (str)
    (if (string-is-integer? str)
        (Right (string→integer str))
        (Left "Not a valid integer"))))

;; Exception handling with try-catch
(define safe-operation : (String → IO (Either Error String))
  (lambda (input)
    (with-handler
      [(IOError e) → (return (Left e))]
      [(ParseError e) → (return (Left e))]
      (do-io
        [result ← (risky-operation input)]
        (return (Right result))))))

Advanced Features

Macros and Metaprogramming

;; Simple macro
(define-syntax when
  (syntax-rules ()
    [(when test body ...)
     (if test (begin body ...) (void))]))

;; Syntax-case macro with hygiene
(define-syntax for
  (lambda (stx)
    (syntax-case stx ()
      [(for (var in list) body ...)
       #'(map (lambda (var) body ...) list)])))

Concurrency

;; Async computation
(define async-computation : (Async Integer)
  (lambda ()
    (do-async
      [x ← (async-read-file "data.txt")]
      [y ← (async-process x)]
      (return y))))

;; Parallel computation
(define parallel-map : (∀ α β. (α → β) → List α → Par (List β))
  (lambda (f lst)
    (par-map f lst)))

Best Practices

  1. Start with Pure Functions: Write pure functions by default, add effects only when necessary
  2. Use Gradual Typing: Begin with dynamic types, add annotations as code stabilizes
  3. Leverage Pattern Matching: Use pattern matching instead of explicit conditionals when possible
  4. Compose Functions: Build complex operations by composing simple functions
  5. Handle Errors Explicitly: Use Maybe, Either, or exception handling for error cases
  6. Document Effects: Make side effects explicit in function types

Learning Path

We recommend studying Lambdust features in this order:

  1. Basic Syntax - Functions, data types, and control structures
  2. Gradual Typing - Adding types incrementally
  3. Effect Systems - Managing side effects
  4. Module System - Organizing larger programs
  5. Dependent Types - Advanced type-level programming
  6. Foreign Interface - Integrating with other languages
  7. Metaprogramming - Macros and compile-time computation
