Type Inference

Lambdust features a sophisticated type inference system that can automatically deduce types for most expressions, reducing the need for explicit type annotations while maintaining type safety.

Γ ⊢ e : τ — Type judgment: expression e has type τ in context Γ

Inference Algorithms

Hindley-Milner Foundation

Lambdust's inference is based on the Hindley-Milner algorithm with extensions for gradual typing and dependent types:

Basic Type Inference

;; No type annotations needed
(define identity (lambda (x) x))
;; Inferred: ∀ α. α → α

(define add (lambda (x y) (+ x y)))
;; Inferred: Number → Number → Number

(define map-example 
  (lambda (f lst)
    (if (null? lst) '()
        (cons (f (car lst))
              (map-example f (cdr lst))))))
;; Inferred: ∀ α β. (α → β) → List α → List β

Bidirectional Type Checking

Lambdust uses bidirectional type checking for dependent types and complex expressions:

;; Synthesis mode: infer type from expression
(lambda (x) (+ x 1))  ⇒  Number → Number

;; Checking mode: check expression against expected type
(lambda (x) (+ x 1)) : (Integer → Integer)  ✓

;; Dependent type inference
(define safe-head
  (lambda (lst)
    (if (null? lst) 
        (error "Empty list")
        (car lst))))
;; Inferred: ∀ α. List α → α (with non-empty precondition)

Gradual Type Inference

The inference system gracefully handles the transition from dynamic to static typing:

Gradual Inference Evolution

;; Stage 1: Completely inferred
(define process-list
  (lambda (lst)
    (map (lambda (x) (* x 2)) lst)))
;; Inferred: List Number → List Number

;; Stage 2: Partial annotation guides inference  
(define process-list
  (lambda ((lst : List α))
    (map (lambda (x) (* x 2)) lst)))
;; Error: Cannot multiply arbitrary type α
;; Suggests: α should be Number

;; Stage 3: Corrected with constraint
(define process-list : (∀ (α : Numeric). List α → List α)
  (lambda (lst)
    (map (lambda (x) (* x 2)) lst)))
;; Type-correct with numeric constraint

Dynamic Type Integration

Inference handles Dynamic types at boundaries:

;; Function with dynamic input
(define process-input
  (lambda (input)  ; input : Dynamic
    (if (number? input)
        (* input 2)    ; Number path
        (string-length input))))  ; String path
;; Inferred: Dynamic → Dynamic

;; Refinement through runtime checks
(define safe-process
  (lambda (input)
    (cond 
      [(number? input) => (lambda (n) (* n 2))]    ; n : Number
      [(string? input) => (lambda (s) (string-length s))]  ; s : String
      [else (error "Invalid input")])))
;; Inferred: Dynamic → Integer

Dependent Type Inference

The system can infer some dependent types automatically:

;; Length-preserving operations inferred
(define reverse-list
  (lambda (lst)
    (define helper
      (lambda (remaining acc)
        (if (null? remaining) acc
            (helper (cdr remaining) 
                    (cons (car remaining) acc)))))
    (helper lst '())))
;; Inferred: ∀ α. List α → List α
;; (Length preservation inferred from structure)

;; Vector operations with dimension inference
(define vector-map
  (lambda (f vec)
    (build-vector (vector-length vec)
                  (lambda (i) (f (vector-ref vec i))))))
;; Inferred: ∀ α β (n : Nat). (α → β) → Vector n α → Vector n β

Effect Inference

Side effects are automatically inferred and tracked:

Effect Inference

;; Pure function (no effects inferred)
(define pure-computation
  (lambda (x y) (+ (* x x) (* y y))))
;; Inferred: Number → Number → Number

;; I/O effects inferred
(define interactive-function
  (lambda (prompt)
    (display prompt)
    (read-line)))
;; Inferred: String → IO String

;; State effects inferred
(define counter
  (let ([count 0])
    (lambda ()
      (set! count (+ count 1))
      count)))
;; Inferred: Unit → State Integer Integer

Polymorphic Inference

Let-polymorphism

Local bindings can be polymorphic:

;; Polymorphic let binding
(define example
  (lambda (x y)
    (let ([id (lambda (z) z)])  ; id is polymorphic here
      (cons (id x) (id y)))))   ; Used at different types
;; Inferred: ∀ α β. α → β → Pair α β

;; Rank-1 restriction prevents issues
(define invalid-example
  (lambda (f)
    (cons (f 42) (f "hello"))))  ; Error: f cannot be polymorphic
;; f would need type: ∀ α. α → α (rank-2)

Type Class Inference

Constraints are inferred from usage:

;; Equality constraint inferred
(define member?
  (lambda (x lst)
    (cond
      [(null? lst) #f]
      [(equal? x (car lst)) #t]  ; Requires Eq constraint
      [else (member? x (cdr lst))])))
;; Inferred: ∀ (α : Eq). α → List α → Boolean

;; Numeric constraints inferred
(define average
  (lambda (numbers)
    (/ (fold-left + 0 numbers)    ; Requires Numeric
       (length numbers))))
;; Inferred: ∀ (α : Numeric). List α → α

Inference Error Messages

Lambdust provides detailed error messages when inference fails:

Helpful Error Messages

;; Type mismatch
(define bad-example
  (lambda (x) (+ x "hello")))

;; Error message:
;; Type error in function application
;; Expected: Number
;; Actual: String  
;; In expression: (+ x "hello")
;; Note: + requires numeric arguments
;; Suggestion: Use string-append for string concatenation

;; Occurs check failure
(define recursive-type
  (lambda (x) (x x)))

;; Error message:
;; Cannot construct infinite type
;; Type variable α occurs in α → β
;; In expression: (x x)
;; Note: This would require α = α → β
;; Suggestion: Consider using explicit recursion

Inference Annotations

Strategic type annotations can guide inference:

;; Minimal annotations for disambiguation
(define complex-function
  (lambda (data)
    (let ([processed : (List Integer) (parse-data data)])
      (map square processed))))
;; Only parse-data result needs annotation

;; Principal type annotations
(define generic-sort : (∀ (α : Ord). List α → List α)
  (lambda (lst) (sort-by compare lst)))
;; Annotation provides principal type

;; Effect annotations
(define file-processor : (String → IO (List String))
  (lambda (filename)
    (map string-trim (read-lines filename))))
;; Effect annotation clarifies intent

Advanced Features

Local Type Inference

Types are inferred locally and propagated:

;; Local inference with propagation
(define process-data
  (lambda (input)
    (let ([numbers (filter number? input)])  ; numbers : List Number
      (let ([doubled (map (lambda (x) (* x 2)) numbers)])  ; x : Number
        (fold-left + 0 doubled)))))  ; Result: Number
;; Full type: List Dynamic → Number

Pattern Match Inference

Pattern matching refines types:

;; Type refinement through patterns
(define process-value
  (lambda (value)
    (match value
      [(Some x) => (lambda () (string-length x))]  ; x : String
      [None => (lambda () 0)])))
;; Inferred: Maybe String → Unit → Integer

Performance Implications

  • Compile-time inference: All type checking happens at compile time
  • Specialization: Polymorphic functions are specialized for performance
  • Elimination: Type information is erased after checking
  • Optimization: Inferred types enable aggressive optimization

Debugging Inference

Tools for understanding and debugging type inference:

;; REPL commands for type inspection
λ> :type (lambda (x) (+ x 1))
Number → Number

λ> :infer map
∀ α β. (α → β) → List α → List β

λ> :explain (lambda (f x) (f (f x)))
Type inference steps:
1. f : α₁, x : α₂  
2. (f x) : α₁ → α₂ → β₁
3. f : β₁ → β₂
4. Unify: α₁ = β₁ → β₂, α₁ = α₂ → β₁
5. Result: (α₂ → β₁) → α₂ → β₂

Best Practices

  1. Start without annotations: Let inference work first
  2. Add strategic annotations: Guide inference at key points
  3. Use principal types: Annotate functions with their most general type
  4. Handle Dynamic carefully: Be explicit about Dynamic type boundaries
  5. Understand error messages: Read inference error messages carefully
