Type System Overview

Lambdust features one of the most advanced type systems in functional programming, combining gradual typing, dependent types, and sophisticated type inference to provide both flexibility and safety.

Core Type System Features

Gradual Typing

Seamlessly transition from dynamic to static typing as your code evolves.

⊢ e : τ ∨ Dynamic

Dependent Types

Types that depend on values enable precise specifications and eliminate runtime errors.

Π(x:A).B(x)

Type Inference

Sophisticated inference algorithms minimize the need for explicit type annotations.

Γ ⊢ e : τ

Blame Tracking

Precise error attribution when static and dynamic code interact.

blame(l, τ, v)

Type Hierarchy

Lambdust's type system is built on a hierarchy of increasingly powerful type constructs:

;; Basic types
Integer, Real, String, Boolean, Character

;; Composite types  
(List α), (Vector n α), (Maybe α), (Either α β)

;; Function types
(α → β), (α → β → γ)

;; Polymorphic types
(∀ α. α → α), (∀ (n : Nat). Vector n α → α)

;; Dependent types
(Π (n : Nat). Vector n α → Vector n α)
{x : Integer | x > 0}  ;; Refinement types

Type Evolution Example

See how a function can evolve from completely dynamic to fully dependent:

Function Evolution

;; Stage 1: Completely dynamic
(define safe-head
  (lambda (lst)
    (if (null? lst) #f (car lst))))

;; Stage 2: Gradual typing
(define safe-head : (∀ α. List α → Maybe α)  
  (lambda (lst)
    (if (null? lst) (None) (Some (car lst)))))

;; Stage 3: Dependent types
(define safe-head : (∀ α (n : Nat). 
                     Vector (+ n 1) α → α)
  (lambda (vec)
    (vector-ref vec 0)))  ;; Guaranteed safe!

Type Safety Guarantees

Lambdust's type system provides several important safety guarantees:

  • Memory Safety: No buffer overflows or null pointer dereferences
  • Type Safety: No runtime type errors in well-typed code
  • Effect Safety: Side effects are tracked and controlled
  • Termination: Dependent types can encode termination proofs

Integration with Effects

The type system seamlessly integrates with Lambdust's effect system:

;; Pure function
(define pure-add : (Integer → Integer → Integer)
  (lambda (x y) (+ x y)))

;; Function with I/O effects
(define interactive-add : (IO Integer)
  (lambda ()
    (do-io
      [x ← (read-integer)]
      [y ← (read-integer)]
      (return (+ x y)))))

;; Function with state effects
(define stateful-counter : (State Integer Integer)
  (lambda ()
    (do-state
      [current ← get-state]
      [_ ← (put-state (+ current 1))]
      (return current))))

Performance Implications

Lambdust's type system is designed for zero-cost abstractions:

  • Compile-time verification: Most type checking happens at compile time
  • Erasure: Type information is erased after compilation for performance
  • Specialization: The compiler generates specialized code for different types
  • Optimization: Type information enables aggressive optimizations

Getting Started with Types

We recommend this learning path for mastering Lambdust's type system:

  1. Start with Gradual Typing - Learn to transition from dynamic to static
  2. Master Basic Types - Understand primitives and composite types
  3. Explore Polymorphism - Generic programming with type variables
  4. Advanced Dependent Types - Value-dependent typing
  5. Understand Inference - How the compiler deduces types
  6. Debug with Blame - Error attribution in mixed code

Learning Tip

Don't try to learn all type system features at once. Start with gradual typing and basic polymorphism, then gradually explore more advanced features as your understanding deepens.
