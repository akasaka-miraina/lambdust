Dependent Types

Dependent types in Lambdust allow types to depend on values, enabling precise specifications that can eliminate entire classes of runtime errors. This powerful type system feature brings mathematical precision to practical programming.

Π(x:A).B(x) — Pi-types (dependent functions)
Σ(x:A).B(x) — Sigma-types (dependent pairs)

Pi-Types (Dependent Functions)

Pi-types represent functions where the return type depends on the input value:

Vector with Length in Type

;; Define a vector type parameterized by length
(define-type (Vector n T)
  (vector-of-length n T))

;; Vector constructor with length proof
(define make-vector : (∀ (n : Nat) (T : Type) 
                        → (x : T) → Vector n T)
  (lambda (x)
    (make-vector-of-length n x)))

;; Usage with compile-time length verification
(define v3 : (Vector 3 Integer)
  (vector 1 2 3))  ;; Length verified at compile time

Safe Array Operations

Dependent types enable array operations that are guaranteed safe at compile time:

;; Safe vector access with bounds checking
(define vector-ref : (∀ (n : Nat) (T : Type) (i : Nat)
                       → Vector n T → (i < n) → T)
  (lambda (vec proof)
    (unsafe-vector-ref vec i)))  ;; Safe due to proof

;; Vector concatenation preserves length information
(define vector-append : (∀ (n m : Nat) (T : Type)
                          → Vector n T → Vector m T → Vector (+ n m) T)
  (lambda (v1 v2)
    (append-vectors v1 v2)))

Sigma-Types (Dependent Pairs)

Sigma-types represent pairs where the second component's type depends on the first:

Database Query Results

;; Query result depends on the schema
(define-type QueryResult
  (Σ (schema : Schema) 
     (rows : List (Row schema))))

;; Type-safe query execution
(define execute-query : (∀ (schema : Schema)
                          → Query schema → IO (QueryResult schema))
  (lambda (query)
    (do-io
      [rows ← (run-sql-query query)]
      (return (make-pair schema rows)))))

Refinement Types

Lambdust supports refinement types that constrain values with predicates:

;; Positive integers
(define-type PositiveInt
  {n : Integer | n > 0})

;; Non-empty lists  
(define-type NonEmptyList
  {lst : List α | (length lst) > 0})

;; Safe division function
(define safe-divide : (Integer → PositiveInt → Integer)
  (lambda ((x : Integer) (y : PositiveInt))
    (/ x y)))  ;; No division by zero possible

Pattern Matching with Refinements

Pattern matching can refine types automatically:

;; List head function with automatic refinement
(define head : (∀ (α : Type) → NonEmptyList α → α)
  (lambda (lst)
    (match lst
      [(cons x xs) → x])))  ;; Pattern proves non-emptiness

;; Compile-time verification of non-emptiness
(define process-items : (List Item → String)
  (lambda (items)
    (if (null? items)
        "No items"
        (item-name (head items)))))  ;; head call is safe

Matrix Operations

Dependent types enable safe linear algebra with dimension checking:

Type-Safe Matrix Multiplication

;; Matrix type with dimensions
(define-type (Matrix rows cols T)
  (matrix-with-dimensions rows cols T))

;; Matrix multiplication with dimension constraints
(define matrix-multiply : (∀ (a b c : Nat) (T : Type)
                            → Matrix a b T 
                            → Matrix b c T 
                            → Matrix a c T)
  (lambda (m1 m2)
    (multiply-matrices m1 m2)))

;; Impossible to call with incompatible dimensions
(define example
  (let ([m1 : (Matrix 3 4 Real) (zeros 3 4)]
        [m2 : (Matrix 4 2 Real) (zeros 4 2)])
    (matrix-multiply m1 m2)))  ;; Result: Matrix 3 2 Real

;; This would be a compile-time error:
;; (matrix-multiply m1 (zeros 3 2))  ;; Error: 4 ≠ 3

Proof Objects

Lambdust allows explicit proof construction for complex properties:

;; Sorted list predicate
(define-type (Sorted lst)
  (sorted-predicate lst))

;; Insertion sort with proof
(define insertion-sort : (∀ (α : Type) → List α → (Σ (result : List α) 
                                                     (Sorted result)))
  (lambda (lst)
    (let ([sorted (sort-algorithm lst)])
      (make-pair sorted (construct-sorted-proof sorted)))))

;; Binary search on proven-sorted lists
(define binary-search : (∀ (α : Type) → (Σ (lst : List α) (Sorted lst)) 
                                       → α → Maybe Nat)
  (lambda (sorted-list target)
    (binary-search-impl (first sorted-list) target)))

Type-Level Computation

Lambdust supports computation at the type level for advanced specifications:

;; Type-level natural number arithmetic
(define-type-function (+ n m)
  (match n
    [Zero → m]
    [(Succ k) → (Succ (+ k m))]))

;; Compile-time list length calculation
(define-type-function (length lst)
  (match lst
    [[] → Zero]
    [(cons x xs) → (Succ (length xs))]))

;; Function with computed dependent type
(define list-take : (∀ (α : Type) (lst : List α) (n : Nat)
                      → (n ≤ (length lst)) 
                      → List α)
  (lambda (lst n proof)
    (take-elements lst n)))

Integration with Gradual Typing

Dependent types work seamlessly with gradual typing:

;; Gradual dependent types
(define process-array
  (lambda (arr)  ;; Type inferred as Dynamic → Dynamic
    (if (array-length arr > 0)
        (vector-ref arr 0)  ;; Runtime bounds check
        #f)))

;; Gradually refine to dependent types
(define process-array-safe : (∀ (n : Nat) (T : Type)
                               → Vector n T → Maybe T)
  (lambda (arr)
    (if (n > 0)
        (Some (vector-ref arr 0))  ;; Proven safe
        None)))

Performance Considerations

  • Compile-time verification: Proofs are erased at runtime for zero-cost abstractions
  • Smart compilation: Dependent type information enables aggressive optimizations
  • Proof inference: Many proofs are constructed automatically by the compiler
  • Gradual refinement: Start with simple types and add dependencies incrementally

Complexity Warning

While dependent types provide strong guarantees, they can make type inference more complex. Use them judiciously, focusing on critical invariants and safety properties.

Practical Applications

  1. Memory Safety: Array bounds checking without runtime overhead
  2. Protocol Verification: State machine protocols verified at compile time
  3. Database Schemas: Type-safe query construction and result handling
  4. Numerical Computing: Dimension-safe linear algebra and scientific computing
  5. Parser Combinators: Grammar constraints encoded in types
