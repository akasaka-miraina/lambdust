Gradual Typing

Lambdust's gradual typing system allows developers to start with dynamic typing and incrementally add static type annotations. This provides the flexibility of dynamic languages during development while offering the safety guarantees of static typing for production code.

Core Concepts

The Dynamic Type

The Dynamic type serves as the bridge between typed and untyped code. Any value can be coerced to Dynamic, and Dynamic values can be used in any context with appropriate runtime checks.

⊢ e : τ ∨ Dynamic

This type judgment means that any expression e has either a concrete type τ or the dynamic type.

Type Evolution

Functions can be gradually annotated, moving from completely dynamic to fully static:

Stage 1: Fully Dynamic
;; No type annotations - fully dynamic
(define add
  (lambda (x y)
    (+ x y)))

;; Type: Dynamic → Dynamic → Dynamic
Stage 2: Partial Annotations
;; Input types specified, output inferred
(define add
  (lambda ((x : Number) (y : Number))
    (+ x y)))

;; Type: Number → Number → Number
Stage 3: Fully Annotated
;; Complete type specification
(define add : (Number → Number → Number)
  (lambda ((x : Number) (y : Number))
    (+ x y)))

;; Type: Number → Number → Number (verified)

Blame Tracking

When runtime type errors occur at the boundary between typed and untyped code, Lambdust's blame tracking system identifies the source of the error:

Example: Blame Assignment

;; Typed function
(define safe-divide : (Number → Number → Number)
  (lambda ((x : Number) (y : Number))
    (/ x y)))

;; Dynamic call with wrong type
(define bad-call
  (lambda ()
    (safe-divide 10 "not-a-number")))

;; Runtime error with blame:
;; Contract violation: expected Number, got String
;; Blame: bad-call (caller) failed to provide Number argument

Advanced Features

Optional Types

Lambdust supports optional type annotations that provide documentation and optional checking:

;; Optional annotation (no runtime checking)
(define factorial :: (Integer → Integer)
  (lambda (n)
    (if (<= n 1) 1
        (* n (factorial (- n 1))))))

;; Enforced annotation (runtime checking)
(define factorial : (Integer → Integer)
  (lambda ((n : Integer))
    (if (<= n 1) 1
        (* n (factorial (- n 1))))))

Polymorphic Gradual Types

Generic functions can be gradually typed using type variables:

;; Polymorphic identity function
(define identity : (∀ (a : Type) → a → a)
  (lambda (x) x))

;; Gradual polymorphic map
(define map-maybe : (∀ (a b : Type) → (a → b) → List a → List b)
  (lambda (f lst)
    (if (null? lst) '()
        (cons (f (car lst))
              (map-maybe f (cdr lst))))))

Performance Implications

Gradual typing in Lambdust is designed for optimal performance:

  • Zero-cost abstractions: Fully typed code compiles to efficient native code
  • Optimized checks: Runtime type checks are minimized through static analysis
  • Specialization: The JIT compiler specializes functions based on observed types
  • Blame elimination: Proven-safe boundaries eliminate runtime checks

Performance Note

While gradual typing provides flexibility, fully typed code will always perform better than mixed typed/dynamic code. For performance-critical sections, consider full type annotation.

Integration with Effects

Gradual typing works seamlessly with Lambdust's effect system:

;; Gradual typing with effects
(define read-file : (String → IO (Either Error String))
  (lambda ((filename : String))
    (with-handler
      [(IO-Error e) → (return (Left e))]
      (do-io
        [content ← (read-file-contents filename)]
        (return (Right content))))))

;; Dynamic wrapper with effect propagation
(define read-file-dynamic
  (lambda (filename)
    (read-file filename)))  ;; Dynamic → IO Dynamic

Best Practices

  1. Start Dynamic: Begin with dynamic types for rapid prototyping
  2. Add Types Incrementally: Annotate function boundaries first
  3. Use Blame Information: Runtime errors provide guidance for type annotation
  4. Prefer Full Typing: Move toward full type annotation for production code
  5. Monitor Performance: Profile mixed typed/dynamic code for optimization opportunities
