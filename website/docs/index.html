Key Features

🎯 Gradual Typing

Start with dynamic types and add static type annotations incrementally. Perfect for both rapid prototyping and production systems.

;; Evolution from dynamic to static
(define factorial         ; Dynamic
  (lambda (n) ...))

(define factorial : (Integer → Integer)  ; Fully typed
  (lambda ((n : Integer)) ...))

🔬 Dependent Types

Types that depend on values enable precise specifications and eliminate runtime errors at compile time.

;; Vector with length in type
(define-type (Vector n T) ...)
(define vector-append : (∀ (n m : Nat) (T : Type)
                          → Vector n T → Vector m T → Vector (+ n m) T)

⚡ Monadic Purity

Referential transparency with controlled side effects through algebraic effects and monadic composition.

;; Effect tracking in types
(define read-file : (String → IO (Either Error String))
  (lambda (filename) ...))

🔗 Foreign Function Interface

Seamless integration with C/C++, Rust, and system libraries while maintaining type safety.

;; Safe foreign function binding
(extern "C" strlen : (CString → CSize))
(extern "Rust" vec_new : (Unit → RustVec α))

Language Philosophy

"Lambdust aims to bridge the gap between mathematical elegance and practical programming, providing the tools necessary for both rigorous theoretical exploration and robust real-world applications."

Design Principles

  • Purity by Default: Referential transparency with explicit effect tracking
  • Gradual Evolution: Start dynamic, evolve to static typing as code matures
  • Mathematical Foundation: Built on solid type theory and category theory
  • Practical Integration: Seamless interoperability with existing ecosystems
  • Academic Rigor: Respect for foundational research while pushing boundaries
