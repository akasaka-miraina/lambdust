REPL Guide

The Lambdust REPL (Read-Eval-Print Loop) is an interactive environment for experimenting, testing, and developing Lambdust programs. It's one of the most powerful tools for learning and rapid prototyping.

Read → Eval → Print → Loop — Interactive Development Cycle

Starting the REPL

Basic REPL Startup

# Start the REPL
lambdust repl

# Output:
# Lambdust REPL v0.2.0
# Type :help for commands, :quit to exit
# λ>

REPL Options

# Start with specific settings
lambdust repl --no-banner          # Hide startup banner
lambdust repl --history-file ~/.lambdust_history  # Custom history
lambdust repl --load lib.ldust     # Preload libraries
lambdust repl --strict-types       # Enable strict type checking

Function Definitions

λ> (define (square x) (* x x))

λ> (square 5)
25

λ> (define factorial 
     (lambda (n)
       (if (<= n 1) 1 (* n (factorial (- n 1))))))
factorial

λ> (factorial 6)
720

Type System Integration

Type Annotations

λ> (define add : (Integer → Integer → Integer)
     (lambda ((x : Integer) (y : Integer)) (+ x y)))
add

λ> :type add
Integer → Integer → Integer

λ> (add 3 4)
7

λ> (add 3.5 4)
Type error: Expected Integer, got Real

Gradual Typing

λ> (define process-input
     (lambda (x)
       (if (number? x)
           (* x 2)
           (string-length x))))
process-input

λ> :type process-input
Dynamic → Dynamic

λ> (process-input 5)
10

λ> (process-input "hello")
5

Working with Libraries

Standard Library Exploration

λ> (import (scheme base))
Imported: scheme base

λ> :doc map
map : ∀ α β. (α → β) → List α → List β

Applies a function to each element of a list, returning a new list.

Examples:
  (map square '(1 2 3 4))  ; => (1 4 9 16)
  (map + '(1 2) '(3 4))    ; => (4 6)

λ> (map (lambda (x) (* x x)) '(1 2 3 4 5))
(1 4 9 16 25)

Interactive Development Workflow

Rapid Prototyping

# 1. Start with a rough idea
λ> (define process-data
     (lambda (data)
       ;; TODO: implement
       data))

# 2. Implement step by step
λ> (define process-data
     (lambda (data)
       (map (lambda (x) (* x 2)) data)))

# 3. Test immediately
λ> (process-data '(1 2 3 4))
(2 4 6 8)

# 4. Refine and add types
λ> (define process-data : (List Number → List Number)
     (lambda ((data : List Number))
       (map (lambda ((x : Number)) (* x 2)) data)))

# 5. Test edge cases
λ> (process-data '())
()

λ> (process-data '(-1 0 1))
(-2 0 2)

Exploratory Programming

# Explore APIs
λ> :doc string-append
λ> (string-append "Hello" " " "World")
"Hello World"

# Try different approaches
λ> (define join-strings
     (lambda (strings)
       (fold-left string-append "" strings)))

λ> (join-strings '("a" "b" "c"))
"abc"

# Compare performance
λ> :time (join-strings (make-list 1000 "x"))
Result: "xxx...xxx"
Time: 15.2ms

# Try alternative implementation
λ> (define join-strings-fast
     (lambda (strings)
       (string-join strings "")))

λ> :time (join-strings-fast (make-list 1000 "x"))
Result: "xxx...xxx"
Time: 0.8ms

     (syntax-rules ()
       [(pp expr) (begin (display 'expr) (display " = ") (display expr) (newline))]))

Best Practices

  1. Use the REPL for experimentation: Try ideas quickly before writing files
  2. Keep definitions small: Test individual functions before combining them
  3. Use :type frequently: Understand what types your expressions have
  4. Save useful definitions: Copy successful experiments to files
  5. Learn the shortcuts: Tab completion and history save time
  6. Use :help: Discover new commands and features

Troubleshooting

Common Issues

  • Infinite loops: Use Ctrl+C to interrupt
  • Memory issues: Use :gc to force garbage collection
  • Type errors: Use :type to understand mismatches
  • File loading problems: Check file paths and syntax

Recovery Commands

λ> [Ctrl+C]        # Interrupt current computation
λ> :reset          # Reset REPL to clean state
λ> :clear          # Clear all definitions
λ> :gc             # Force garbage collection
λ> :memory         # Check memory usage
