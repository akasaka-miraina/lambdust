Lambdust combines the mathematical elegance of pure functional programming with gradual typing, dependent types, and algebraic effects. R7RS-compliant with modern innovations.

Language Features

Gradual Typing

Start with dynamic typing and add static types incrementally. Perfect for both rapid prototyping and production systems.

⊢ e : τ ∨ Dynamic

Dependent Types

Types that depend on values enable precise specifications and eliminate entire classes of runtime errors.

Π(x:A).B(x)

Monadic Purity

Referential transparency with controlled side effects through algebraic effects and monadic composition.

M(A) >>= (A → M(B)) → M(B)

R7RS Compliant

Full compatibility with Scheme R7RS standard while adding modern type system innovations.

R7RS ⊂ Lambdust

High Performance

JIT compilation, SIMD optimizations, and advanced memory management for production workloads.

O(1) → O(n) optimized

Foreign Function Interface

Seamless integration with C/C++, Rust, and system libraries while maintaining type safety and purity.

extern "C" : (CInt → IO CInt)

Rich Ecosystem

Comprehensive standard library with SRFI implementations and extensive documentation.

∀ SRFI. supported(SRFI)

Code Examples

Gradual Typing Evolution

;; Start with dynamic typing
(define fibonacci
  (lambda (n)
    (if (<= n 1) n
        (+ (fibonacci (- n 1)) 
           (fibonacci (- n 2))))))

;; Add type safety incrementally
(define fibonacci-typed : (Integer -> Integer)
  (lambda ((n : Integer))
    (if (<= n 1) n
        (+ (fibonacci-typed (- n 1))
           (fibonacci-typed (- n 2))))))

Type inference: fibonacci-typed : Integer → Integer

Dependent Types for Safety

;; Vector with length tracked in type
(define-type (Vec n a) 
  (vector-of-length n a))

;; Safe vector operations with length preservation
(define vector-append : (∀ (a : Type) (n m : Nat)
                          -> Vec n a -> Vec m a -> Vec (+ n m) a)
  (lambda (v1 v2)
    (append-vectors v1 v2)))

;; Matrix operations with dimension checking
(define matrix-multiply : (∀ (a b c : Nat)
                            -> Matrix a b -> Matrix b c -> Matrix a c)
  (lambda (m1 m2) ...))

Dimension safety: ✓ Impossible to multiply incompatible matrices

Monadic Purity with Effects

;; Pure computation with effect tracking
(define-effect IO)
(define-effect State)

(define pure-computation : (Integer -> Integer)
  (lambda (x) (* x x)))

;; Effectful computation with explicit tracking
(define effectful-computation : (Integer -> (IO State Integer))
  (lambda (x)
    (do-monad
      [y <- (read-state)]
      [_ <- (write-state (+ y 1))]
      [_ <- (print (format "Processing: ~a" x))]
      (return (* x y)))))

Effect tracking: ✓ No hidden side effects

Research Foundation

Type Theory Foundations

Building upon Martin-Löf Type Theory and Homotopy Type Theory

  • Intuitionistic Type Theory — Per Martin-Löf (1984)
  • Homotopy Type Theory — Univalent Foundations Program (2013)

Lambdust Innovations:

  • Practical dependent types for systems programming
  • Bidirectional type checking with inference
  • Universe polymorphism with level inference

Gradual Typing Systems

Extending the seminal work on gradual typing for functional languages

  • Gradual Typing for Functional Languages — Siek & Taha (2006)
  • Blame for All — Wadler & Findler (2009)

Lambdust Innovations:

  • Monadic gradual typing with effect tracking
  • Optimized runtime type checking
  • Blame tracking for debugging type errors

Effect Systems & Monads

Algebraic effects and monadic programming for pure functional computation

  • Algebraic Effects and Handlers — Plotkin & Pretnar (2013)
  • Monads for Functional Programming — Philip Wadler (1995)

Lambdust Innovations:

  • Handler-based effect system
  • Monad transformer optimization
  • Referential transparency with controlled effects
